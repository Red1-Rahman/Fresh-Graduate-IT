Contributing to Fresh Graduate IT

Thank you for contributing to Fresh Graduate IT.

This project exists to make high-quality preparation and learning materials freely available to students and fresh graduates in Computer Science, Software Engineering, Information Technology, Information Systems, and related disciplines.

You do not need to be an expert to contribute. Finding an error, improving an explanation, adding useful questions, fixing a diagram, or suggesting better resources are all valuable contributions.

Ways to Contribute

You can contribute by:

* Adding new preparation materials
* Improving existing study materials
* Correcting factual or grammatical errors
* Adding or improving practice questions
* Improving explanations
* Updating outdated information
* Creating useful diagrams
* Improving accessibility
* Adding preparation resources for new examinations or career paths
* Reviewing pull requests
* Reporting non-security issues
* Suggesting improvements to the repository

Basic Contribution Workflow

The recommended workflow is:

1. Fork this repository.
2. Create a new branch for your contribution.
3. Make your changes.
4. Compile and check any affected LaTeX documents.
5. Review the generated PDF visually.
6. Commit both the updated LaTeX source and the corresponding PDF when applicable.
7. Push your branch to your fork.
8. Open a Pull Request against this repository.
9. Explain what you changed and why.

For small corrections, you may also use GitHub’s web editor if appropriate.

LaTeX and PDF Requirements

For documents maintained in both formats:

source.tex  →  compiled PDF

The LaTeX source is the source of truth.

When modifying an existing document, contributors should update the .tex source and regenerate the corresponding .pdf.

Please do not manually edit a PDF while leaving its LaTeX source unchanged.

Before submitting a contribution:

* Make sure the document compiles successfully.
* Check the generated PDF visually.
* Check for missing content, broken references, incorrect page breaks, and layout problems.
* Avoid unnecessary LaTeX compilation artifacts in commits.
* Keep the source and compiled PDF synchronized.

Automated checks will also run on pushes and Pull Requests.

Content Quality

Contributions should be:

* Accurate and educationally useful
* Clear and understandable
* Relevant to the intended audience
* Properly structured
* Free from unnecessary duplication
* Based on reliable information
* Reviewed for spelling and grammar
* Updated when the underlying syllabus, examination, or technology changes

If you are unsure about a factual claim, provide a reliable reference where practical.

Accessibility

Accessibility is an important part of this project.

When creating diagrams and visual materials:

* Prefer the Okabe-Ito color palette where appropriate.
* Do not communicate information using color alone.
* Use labels, shapes, patterns, symbols, or line styles as additional cues.
* Maintain sufficient contrast.
* Avoid relying exclusively on red and green to distinguish information.
* Make diagrams understandable in grayscale where practical.

The goal is to make the materials useful to as many learners as possible.

Copyright and Licensing

Only contribute material that you have the right to distribute.

Do not submit:

* Pirated books or course materials
* Copyrighted PDFs without redistribution permission
* Unlicensed copies of examination papers where redistribution is prohibited
* Images, diagrams, or text copied from third parties without appropriate permission or licensing
* Material that violates another person’s intellectual property rights

When using third-party material, retain its original licensing requirements and provide appropriate attribution.

Unless otherwise stated, original educational content contributed to this project is intended to be released under CC BY-SA 4.0.

Keep Contributions Focused

Whenever possible, keep each Pull Request focused on one logical change.

For example:

Good:
Fix networking questions in MSc CSE preparation
Good:
Add operating systems section
Good:
Correct diagrams in BCS preparation
Less ideal:
Rewrite five unrelated preparation books in one PR

Focused Pull Requests are easier to review, test, and maintain.

Pull Requests

When opening a Pull Request, explain:

* What you changed
* Why the change is useful
* Which materials are affected
* Whether the LaTeX source and PDF were updated
* Any sources or references that support the change

Please respond to review feedback and update your branch when necessary.

Automated checks may be required to pass before a Pull Request can be merged.

Issues

For normal problems, suggestions, factual errors, and requests for new materials, use the appropriate GitHub Issue mechanism.

Do not use public Issues to report security vulnerabilities.

Security vulnerabilities should be reported privately through the repository’s Security tab. See SECURITY.md.

Future Contribution Templates

GitHub Issue Templates and Pull Request Templates will be added as the project evolves.

Once available, this document will be updated with instructions for using those templates.

Code of Conduct

Please communicate respectfully and constructively.

Fresh Graduate IT is intended to be a collaborative educational project. Differences in knowledge, academic background, opinions, and experience are expected. Contributions should be evaluated based on their educational value, accuracy, quality, and relevance.

Please see CODE_OF_CONDUCT.md for the project’s complete community guidelines.

Thank You

Every contribution helps another student or graduate.

Whether you contribute an entire preparation guide or fix a single typo, your work can make these materials more useful to someone else.

Learn. Prepare. Contribute.
